# 架构说明

## 1. 设计目标

这个项目有三个同时存在的目标，架构必须同时服务它们：

1. **能作为赛事作品提交** —— 需要公网可访问、可交互、零环境依赖；
2. **能作为真实开源软件长期维护** —— 需要清晰的模块边界、可测试、可扩展；
3. **能覆盖 PRD 描述的多终端** —— Web、Windows、macOS、Android。

矛盾的焦点在第 1 点和第 3 点：赛事要的是「一个 URL」，PRD 要的是「系统级接管」。
我们的解法是**把逻辑与形态彻底分开**。

### 核心层的第一原则：不读系统时间

`packages/core` 里**没有任何一处直接调用 `new Date()` 或 `Date.now()`** 来做逻辑判断。
当前时间一律由调用方注入：

```js
// 引擎构造时要求注入时钟
const engine = createEngine({ settingsStore, quotaStore, now: () => new Date() });

// 测试里可以任意穿越时间
let currentTime = at(2026, 8, 31, 23, 30);   // 周一 23:30
const engine = createEngine({ settingsStore, quotaStore, now: () => currentTime });
currentTime = at(2026, 9, 1, 0, 0);          // 跨到周二 0 点
```

这个约束看起来很小，但它决定了整个项目能否被可信地验证：

- 「周日晚用掉的额度，周一 0 点恢复」这种需求，只能在可控时钟下测；
- 「凌晨 02:00 归属到前一天开启的熄灯时段」这种边界，也只有可控时钟能测；
- 三端共用同一份判定，不会出现「Web 上 23:00 熄灯、桌面上 23:05 熄灯」。

真实的时钟只出现在一个地方：Web 端的 `createEngine({ now: () => new Date() })`。

## 3. 相位模型

整个应用的状态由 `phaseAt()` 一个函数决定，返回四种相位之一：

```
┌──────────────────────────────────────────────────────────┐
│  off      计划已关闭，或本次时段已被紧急解除                 │
│  idle     计划生效中，距离熄灯开始尚早                      │
│  warning  进入提前预告窗口，不可关闭的倒计时弹窗             │
│  active   强制熄灯中，全屏黑屏界面                          │
└──────────────────────────────────────────────────────────┘
```

**视图显隐完全由相位驱动，不接受任何用户操作直接修改。**
编排层每 250ms 调用一次 `applyPhase(snapshot)`，它是「到点自动接管」的唯一入口。

### 跨天时段的判定

熄灯时段默认是 23:00 → 次日 07:00，横跨午夜。所以「此刻是否在熄灯中」必须同时检查
**今天开启的时段**和**昨天开启的时段**：

```js
export function activeWindowAt(plan, now) {
  for (const offset of [0, -1]) {                    // 只需检查这两天
    const w = windowForDate(plan, addDays(now, offset));
    if (w && now >= w.start && now < w.end) return w;
  }
  return null;
}
```

偏移 0 与 −1 天就够，因为单次时段必然短于 24 小时。

### 紧急解除的作用域

紧急解除**只解除当前这一次时段**，而不是「当天」。实现上记录被解除时段的**开始日**：

```js
dismissedWindowKey = phaseInfo.window?.startKey;   // 例如 "2026-08-31"
```

这样 8/31 23:00 的时段被解除后，整个 8/31 23:00 → 9/1 07:00 都保持解除状态，
而 9/1 23:00 的新时段会照常生效 —— 这正是 PRD「次日按计划自动生效」的准确语义。

## 4. 依赖方向

```
constants
time
holidays   → time
schedule   → constants, time, holidays
scene      → holidays, time
copy       → scene
quota      → time, constants
whitelist  → time
storage
settings   → constants, storage
password
ai         → scene
audio
guard      → constants
engine     → constants, copy, password, scene, schedule
```

依赖图无环。`packages/core/src/index.js` 用 `export *` 汇总，这里有一个**容易被忽略的坑**：
若两个模块导出了同名符号，`export *` 会**静默**排除该名字而不是报错，排查起来非常痛苦。
因此新增模块时请确保导出名全局唯一；构建脚本还会扫描发布产物是否残留仓库内路径引用。

## 5. 存储与容错

三条铁律：

1. **读取永远不能抛异常。** localStorage 在无痕模式、配额耗尽、被企业策略禁用时都会直接抛错。
   所有读取都包在 `try/catch` 里，失败时回退到内存实现或默认值。
2. **数据损坏必须自愈。** JSON 解析失败时清掉坏数据、回到默认值，
   **绝不能因为存储异常把用户锁死在熄灯界面里**。
3. **写入失败不是致命错误。** `createStore().write()` 返回 `false` 而不是抛错。

`migrateSettings()` 是唯一的设置入口：任何字段缺失、类型错误、版本过期都会被收敛到合法状态
（数值夹到区间内、数组元素做结构校验、已废弃字段清理、系统白名单应用强制补回）。

## 6. 编排层（Web 端）

`apps/web/src/app.js` 是唯一接触真实时钟与 DOM 的地方：

| 职责 | 实现 |
| --- | --- |
| 主循环 | `setInterval(tick, 250)`，每帧重算相位并渲染 |
| 相位应用 | `applyPhase()`，用**令牌**作废过期的异步切换（入场动画期间相位可能又变了） |
| 演示模式 | 让评审不必等到 23:00；只**加强**熄灯状态，永不削弱 |
| 改时间冻结 | 检出跳变后冻结到**原时段结束时刻**，改时间只会更甩不掉 |
| 守卫装配 | 历史栈围栏、`beforeunload`、Wake Lock；**演示模式下不装**，避免把评审困住 |
| 白名单计费 | 离开页面时开始计时，回来时按实际经过时间结算 |

### 演示模式的设计取舍

赛事评审不可能等到晚上 23:00 才看效果，所以主页提供「立即体验熄灯模式」。
它有两个刻意的限制：

- **只能加强，不能削弱**：`effectivePhase()` 中演示模式是一个**优先返回 active** 的短路分支，
  不存在「用演示模式绕过熄灯」的可能；
- **自动过期**：2 分钟后自动结束，并且**不安装**防绕过守卫（历史围栏 / beforeunload），
  避免把评审困在界面里。

## 7. 为什么音频不用素材文件

五类音色全部用 Web Audio API 实时合成：

| 音色 | 合成方式 |
| --- | --- |
| 白噪音 | 白噪声缓冲 → 0.28 增益 |
| 雨声 | 白噪声 → 高通 900Hz + 低通 7kHz，0.15Hz LFO 调制音量 |
| 溪流声 | 白噪声 → 高通 500Hz + 带通 1.8kHz，0.4Hz LFO 调制中心频率 |
| 海浪声 | 布朗噪声 → 低通 700Hz，0.08Hz LFO 调制音量 + 0.05Hz 扫描截止频率 |
| 篝火声 | 布朗噪声 → 低通 500Hz 打底 + 随机高频爆裂脉冲 |

噪声采样生成是纯函数 `generateNoiseSamples({ length, type, random })`，
因此**可以在 Node 里做统计性质验证**（白噪声直流偏移接近 0、布朗噪声相邻样本相关性显著更高）。

不用音频文件的三个理由：

1. **零版权风险** —— 赛事明确要求参赛素材必须享有合法权利，合成音不存在这个问题；
2. **零体积** —— 应用仍然可以完全离线运行；
3. **无限循环无接缝** —— 噪声缓冲天然无缝，采样音频有循环点。

## 8. 构建与部署

应用代码**本身不需要构建**（原生 ES Module、零依赖、零转译）。
`scripts/build.mjs` 只做一件事：把分处两个目录的代码拼成一个自包含的静态站点。

```
apps/web/*        →  dist/*
packages/core/*   →  dist/core/*

apps/web/src/core.js 的唯一 import 被改写：
  "../../../packages/core/src/index.js"  →  "../core/src/index.js"
```

整个 Web 应用只通过 `src/core.js` 访问核心包，所以**只有这一个文件需要改写**。
构建脚本在最后扫描发布产物，确认没有残留指向仓库源码的 import 说明符
（扫描使用正则匹配 import 语句，而不是无脑搜字符串，避免把注释里的提及误判为泄漏）。

发布产物约 440 KB，无外部请求，可直接托管在任意静态服务上。

## 9. 有意为之的取舍

| 取舍 | 选择了 | 放弃了 | 理由 |
| --- | --- | --- | --- |
| 依赖 | 零第三方依赖 | 生态便利 | 保证离线可用、无供应链风险、十年后仍能跑 |
| 构建 | 零构建 + 原生 ESM | 打包优化 | 模块边界清晰，无需工具链即可调试 |
| 时间 | 全部注入 | 直接读系统时间 | 可测试性；跨端一致性 |
| 音频 | 实时合成 | 素材音质 | 零版权风险；零体积 |
| 密码 | 固定域分隔 + SHA-256 | 慢哈希 / KDF | 它是防冲动的减速带，不是安全机制；见 DECISIONS |
