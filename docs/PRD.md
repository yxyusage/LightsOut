## 一、产品概述

### 1.1 产品名称
熄灯早睡

### 1.2 产品定位
一款跨终端的强制型睡眠辅助工具，通过到点全屏接管设备、限制娱乐应用的强干预方式，
解决年轻人「有早睡意愿但自控力不足、睡前刷手机无节制」的核心问题。

### 1.3 核心解决痛点
- 认知上知晓熬夜危害，但行为上无法抵制短视频、游戏等内容的即时诱惑
- 普通睡眠 APP 仅具备提醒功能，无强制阻断能力，极易被忽略或跳过
- 缺少外部强制约束，睡前刷手机时间不断延后，睡眠时长持续不足

### 1.4 目标用户
18–30 岁年轻群体（学生、职场新人），有早睡诉求但自控力较弱，长期受熬夜困扰的用户。

### 1.5 终端范围
- 移动端：Android 优先开发，iOS 后续迭代评估
- PC 端：Windows、macOS 同步规划开发，核心逻辑与移动端对齐

## 二、核心功能模块

### 2.1 睡眠计划管理模块

#### 2.1.1 熄灯时段设置

| 需求 | 状态 | 实现位置 |
| --- | --- | --- |
| 支持分别设置工作日、周末两套独立的熄灯时段，默认推荐值 23:00 – 次日 07:00 | ✅ | `schedule.js` 的 `windowForDate()` |
| 支持一键开启 / 关闭当日熄灯计划 | ✅ | `settings.plan.enabled`，主页按钮 |
| 时段设置精确到分钟，结束时间支持跨天 | ✅ | `<input type="time">` + `crossesMidnight` 判定，有单测覆盖 |

#### 2.1.2 提前预告提醒

| 需求 | 状态 | 实现位置 |
| --- | --- | --- |
| 自定义提前提醒时长（默认 15 分钟，可选 10/15/30 分钟） | ✅ | `WARN_MINUTE_OPTIONS` |
| 到达提醒时间后弹出全屏半透明预告弹窗，显示倒计时 | ✅ | `#screen-warning` + `createWarningView()` |
| 预告弹窗不支持关闭，倒计时结束后自动进入熄灯模式 | ✅ | 弹窗无关闭控件；相位由 `phaseAt()` 单向驱动，用户无法干预 |

#### 2.1.3 每周解除额度机制

| 需求 | 状态 | 实现位置 |
| --- | --- | --- |
| 每周 2 次紧急解除额度，自然周周一 0 点自动重置 | ✅ | `quota.js` 的 `weekKeyOf()`，有跨周单测 |
| 额度用完后本周内无法再通过紧急解除退出 | ✅ | `engine.emergencyUnlock()` 返回 `quota-exhausted` |
| 个人中心可查看本周剩余解除次数 | ✅ | 个人中心的额度圆点与文案 |

### 2.2 强制熄灯模式

#### 2.2.1 进入触发逻辑

| 需求 | 状态 | 说明 |
| --- | --- | --- |
| 到达设定的熄灯开始时间，自动触发熄灯模式 | ✅ | `app.js` 的 250ms 主循环调用 `applyPhase()` |
| 触发后先播放「拉灯绳灭灯」入场动画，动画结束后进入全屏黑屏界面 | ✅ | `lib/lamp.js` + CSS 关键帧，1.5 秒 |
| 熄灯时段内，用户解锁设备后将直接进入熄灯黑屏界面，不会跳转至系统桌面 | 🟡 | Web 版用 `visibilitychange` 重新接管 + PWA standalone 全屏；**真正的系统桌面拦截需要原生端** |
| 设备重启后，若当前时间仍处于熄灯时段内，自动恢复进入熄灯模式 | 🟡 | Web 版刷新或重开即恢复；重启级恢复见 Android 端的 BootReceiver |

#### 2.2.2 黑屏主界面内容

| 需求 | 状态 |
| --- | --- |
| 纯黑背景，低亮度白色文字 | ✅ |
| 基础信息区：当前实时时间、距离本次熄灯结束的剩余时长 | ✅ |
| 文案展示区：轮播展示熬夜危害科普数据、情绪安抚语句 | ✅ 每条科普绑定文献来源，可一键溯源 |
| 开启 AI 文案功能后，替换为场景化生成的个性化文案 | ✅ |
| 功能入口区（底部）：白名单应用入口、助眠音乐入口 | ✅ |
| （隐藏）紧急解除触发区域 | ✅ 连续点击屏幕 5 次 |

#### 2.2.3 白名单应用规则

| 需求 | 状态 | 说明 |
| --- | --- | --- |
| 用户可自行添加允许在熄灯模式下使用的应用 | ✅ | 名称 + 可选打开地址 |
| 系统自带电话、短信默认加入白名单且不可移除、无时长限制 | ✅ | `SYSTEM_WHITELIST_APPS`，`removable: false`、`countsAgainstQuota: false` |
| 所有白名单应用共用总可用时长，支持自定义，上限 60 分钟 | ✅ | `whitelist.js` |
| 从黑屏界面点击白名单入口，可选择并打开对应应用；使用时长实时扣减 | ✅ | 离开页面时开始计时，回来时按实际经过时间结算 |
| 总时长耗尽后自动退回熄灯黑屏界面，当日无法再使用 | ✅ | 见 DECISIONS.md 关于「当日」的语义澄清 |
| 第三方通信软件默认不在白名单内，需手动添加并占用额度 | ✅ | 默认仅含电话与短信 |

#### 2.2.4 系统基础功能放行规则

| 需求 | 状态 | 说明 |
| --- | --- | --- |
| 系统来电、短信、闹钟默认不受熄灯模式限制 | 🟡 | Web 版通过 `tel:` / `sms:` 协议放行；系统级来电浮层需原生端 |
| 通话结束后自动退回熄灯黑屏界面 | 🟡 | Web 版回到页面即重新接管 |

#### 2.2.5 退出逻辑

| 需求 | 状态 |
| --- | --- |
| 自动退出：到达熄灯结束时间，播放「拉灯绳亮灯」退场动画后恢复 | ✅ |
| 紧急解除：连续点击屏幕 5 次触发，输入预设密码后可退出 | ✅ |
| 每解除一次消耗 1 次每周额度，额度为 0 时入口不可用 | ✅ 且**密码错误不消耗额度** |
| 紧急解除后当日熄灯模式失效，次日按计划自动生效 | ✅ |

### 2.3 助眠音频功能

| 需求 | 状态 | 说明 |
| --- | --- | --- |
| 内置助眠白噪音库：海浪、溪流、雨声、篝火、纯白噪音 | ✅ | `audio.js` |
| 支持设置播放时长：15 / 30 / 60 分钟 / 持续至熄灯结束 | ✅ | `AUDIO_DURATION_OPTIONS` |
| 熄灯模式下可随时从底部入口开启 / 关闭音频，支持独立音量调节 | ✅ | 音频浮层 |
| 音频在熄屏状态下可持续后台播放，播放结束后自动停止 | ✅ | 熄屏不中断，到点自动停止 |

> **实现取舍**：五类音色全部用 Web Audio API **实时合成**，不加载任何音频文件。
> 这样做同时解决了三个问题：零版权风险（赛事要求参赛素材享有合法权利）、零体积、
> 无限循环无接缝。合成参数见 `audio.js` 顶部注释。

## 三、防绕过安全防护体系（核心）

| 需求 | Web/PWA | 原生端 |
| --- | --- | --- |
| 前台服务保活 | 🟡 Service Worker + Wake Lock | ✅ 前台服务 + 常驻通知 |
| 禁止强制停止 | ❌ 浏览器无此能力 | ✅ 设备管理员 |
| 禁止清理后台 | 🟡 Service Worker 常驻 | ✅ 锁定后台进程 |
| 防系统时间篡改：立即恢复熄灯，记录违规，**不重置剩余时长** | ✅ `createClockGuard()` + 冻结到原时段结束时刻 | ✅ TimeChangeReceiver |
| 防多开 / 虚拟环境 | ❌ | 🟡 可扩展 |
| 重启自动恢复 | 🟡 重新打开即恢复 | ✅ BootReceiver |
| 防卸载保护 | ❌ | ✅ 设备管理员 |

> **诚实标注**：浏览器沙箱内无法实现真正的进程级防护。上表刻意区分了两端的实际能力，
> 不做夸大宣传。详见 README 的「技术形态与能力边界」一节。

## 七、后续迭代方向建议（V1.0 暂不纳入）

- 睡眠数据统计：每日熄灯时长、中途解除次数、白名单使用时长，生成周 / 月报告
- 早睡打卡奖励：连续打卡解锁成就、专属文案
- 小憩模式：20–90 分钟午休 / 小憩短时锁定
- 睡眠健康分析：结合熬夜数据给出个性化改善建议
- 好友功能：多种方式添加好友，显示好友睡眠信息

规划与优先级见 ROADMAP.md。
