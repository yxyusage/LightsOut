四类检查：

| 检查 | 为什么值得放进 CI |
| --- | --- |
| **相对 import 可解析** | 拼错路径在浏览器里只表现为白屏 + 一条控制台报错，本地很难第一时间发现 |
| **Markdown 相对链接可解析** | 文档最容易在重构后悄悄失效 |
| **Service Worker 预缓存清单** | 写错文件名不会让安装报错，却会让熄灯界面在**断网时打不开** —— 而断网正是用户最容易用来绕过熄灯的手段 |
| **时钟可注入不变量** | `packages/core` 中不允许直接读系统时间，这是全部时间相关测试能成立的前提 |

后两项检查在本次开发中**各抓到一个真实缺陷**：

- `sw.js` 预缓存了不存在的 `views/warning.js`（预告弹窗其实在 `blackout.js` 里），
  同时漏掉了 `controls.js` 与 `onboarding.js`；
- `sw.js` 预缓存了不存在的 `./core/index.js`。

两者都会在断网时造成 404。已修复并有检查守住。

| **真实大模型调用** | 🟡 部分验证 | 用假 fetch 覆盖了成功/失败/超时/降级路径；未用真实 Key 跑通 |
| **音频实际听感** | 🟡 部分验证 | 合成算法有统计性质测试；未做主观听感评估 |

### 一个必须说清楚的边界

浏览器沙箱内**无法真正阻止用户打开微信或抖音**。本项目在 Web 端实现的是
「专注接管 + 时段锁定」的等效体验：熄灯状态本身甩不掉（改时间、切走、刷新、返回键都无效），
但用户仍然可以使用其它 App。要做到系统级接管，必须使用原生端 ——
这一点写在 README、引导页第 1 步与 `docs/DECISIONS.md` 中，**不做夸大宣传**。
